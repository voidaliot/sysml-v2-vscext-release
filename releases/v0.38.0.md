### Added

- A case now shows what it binds. Hover a case usage for the definition it performs, the subject and actors it inherits, and what its objective is measured against.
- An objective card says whether its subject is the case subject (verification and use cases) or the case result (plain and analysis cases), and lists the subrequirements a `verify` inside it requires.
- An include card names the use case it references, says it is not copied, and gives the subject it is investigated on.
- Four new checks: `SSM045` for a case usage typed by two case definitions, `SSM046` for an objective subject the case cannot bind, `SSM047` for an included use case whose subject is not the including one, `SSM048` for an `actor` binding naming no parameter of the included use case.

### Fixed

- Case View drew the same actor once per use case. The same actor now appears once, with a line to each case it takes part in, as the subject already did.
- An actor bound by a usage (`actor :>> driver = ...`) joined the actor it redeclares instead of drawing a second figure, and is labelled with its name and type.
- An actor with no name of its own was labelled "subject" on the diagram.
- A usage that binds its definition's subject (`subject :>> vehicle = ...`) drew a second identical boundary. It shares one now, unless usages bind different things.
